# Разработка Retaliation Hints

## 1. Структура

`source/` содержит код мода, `installer/` установку и удаление, `Docs/` инструкции. Проверки находятся в `development/tests/`, результаты сборки и локальные материалы в `development/artifacts/`, исключённом из Git. [Заметки об игровых методах](NATIVE-NOTES.md) и [сохранённая версия 0.1.8](STABLE-BASELINE.md) хранятся рядом.

## 2. Сборка и проверки

Нужны Windows, Git, Windows PowerShell 5.1, .NET SDK 8 или новее и совместимая копия игры с BepInEx 6.0.0-be.788. Библиотеки из `BepInEx/interop` используются при сборке и не входят в репозиторий.

Команды из корня проекта:

```powershell
dotnet build .\source\RetaliationHints.csproj -c Release '-p:GameRoot=<папка игры>'
dotnet run --project .\development\tests\RetaliationHints.Tests.csproj -c Release -- '<папка игры>\HeroesOldenEra_Data\StreamingAssets\Core.zip'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\development\tests\Installer.Tests.ps1
```

Плагин собирается для .NET 6, проверки для .NET 8. Проверяются арифметика потерь, временные существа, лечение, упреждающая ответка, привязка подсказки, размещение, наблюдение боевых событий и повторная обработка сохранённых данных. Установщик проверяется в искусственных папках: обновление, резервные копии, сохранение других модов и настроек, удаление и запуск из исходников.

Проверки не запускают игру и не подтверждают все механики боя. Версия 0.1.13 сохраняет расчёт и наблюдатель 0.1.12. Старые результаты сверки относятся к указанным в них версиям, а не к новому игровому испытанию 0.1.13.

Повторная обработка журнала старого формата:

```powershell
dotnet run --project .\development\tests\RetaliationHints.Tests.csproj -c Release -- --audit-replay '<журнал 0.1.11.jsonl>' '<отчёт.json>'
```

Команда не восстанавливает события, отсутствующие в исходной записи. [Устройство сверки](../Docs/combat-audit.md).

## 3. Установочный архив

Сначала зафиксируйте изменения. Сборщик использует выбранный коммит:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\development\Build-Release.ps1 -GameRoot '<папка игры>' -Revision HEAD
```

Сборщик проверяет игровые файлы, запускает проверки, собирает DLL и сверяет версии проекта и Plugin.cs. Зависимости закреплены в `development/release-settings.json`. Параметры `-LoaderArchive` и `-UnityLibrariesArchive` принимают локальные архивы с совпадающими SHA-256.

В `development/artifacts/releases/` создаются ZIP, `.zip.sha256` и `.release.json`. Параметр `-OutputDirectory` меняет папку результата. Существующие файлы не перезаписываются. ZIP содержит `Install.bat`, `Uninstall.bat`, `_files`, README, LICENSE и Docs. Личные настройки и журналы боя в него не входят.

`release-manifest.json` связывает поставляемые файлы с коммитом и SHA-256, `_files/manifest.json` описывает установку. Поля `prerelease = true` и `gameplayVerified = false` обозначают предварительный выпуск и отсутствие игровой проверки в сборщике.

## 4. Выпуск

Используйте новый тег `v<версия>` на проверенном коммите. В GitHub Release включается отметка `Pre-release`. В описании выпуска явно указываются неполнота расчёта, приблизительность результата и известные ограничения. Загрузите ZIP, SHA-256 и сведения о сборке, затем скачайте архив и проверьте контрольную сумму.

Репозиторий открыт. Предупреждение о неполном расчёте и отметка предварительного выпуска сохраняются. Существующие теги, выпуски и сохранённая версия 0.1.8 не заменяются. Сборщик не устанавливает мод и не запускает игру; игровые проверки выполняет пользователь.
